The module defines a four-service topology in `docker-compose.yml`: a `redis` service (Redis 7 Alpine with AOF persistence and 1 GB max memory) shared by both application processes; an `api` process (Node.js on port 4000) and an `engine` process (Node.js on port 4100), both built from the sibling `../backend` directory and differentiated via the `APP_PROCESS` env var; and an `nginx` reverse proxy that terminates TLS using certificates mounted from an external `certbot-certs` volume. `nginx/nginx.conf` sets global worker/connection tuning and WebSocket upgrade mapping, while `nginx/site.conf` defines upstreams to `api:4000` and `engine:4100`, routes `/api/*` to the API, `/ws` to the engine (with long read/send timeouts for live market streaming), and exposes `/health` against the API. All secrets and runtime config flow through a `.env` file (template in `.env.example`) covering MongoDB Atlas, JWT keys, OTP pepper, SMS/SMTP providers, Razorpay, and Upstox market feed credentials. The compose file enforces startup ordering via `depends_on` with `service_healthy` conditions and includes healthchecks for all services.
